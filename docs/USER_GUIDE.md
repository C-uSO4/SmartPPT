# SmartPPT 使用说明

## 打开与生成

1. 打开 **[SmartPPT 在线版](https://smart-ppt-ten.vercel.app/)**，不需要登录、安装 Python 或 Node.js，也不需要保持本地服务窗口开启。Windows 用户也可双击项目中的 `启动网页版.bat` 打开该公开地址。建议使用最新版 Chrome、Edge 或 Safari。
2. 上传 DOCX、Markdown、TXT 或初代 PPTX；未上传模板时，可选择纸感编辑、深色发布会或清透商务风格。没有文件时可使用示例大纲。
3. Markdown 若使用图片，在“图片素材”中一起选择同名 PNG/JPEG，并在正文中写 `![图片说明](文件名.png)`。最多 12 张，单张不超过 8 MB，合计不超过 20 MB。
4. 如需套版，在“PPT 模板（可选）”中选择另一份 PPTX；不需要模板时保持为空。上传模板后，程序从全部模板页挑选真实版面并填入内容，视觉风格选择不再控制自生成布局。
5. 默认不开启 AI，全部内容在本机浏览器处理。若需要 AI 辅助识别标题与正文，可主动勾选该选项；此时仅待分类文字块会经本站代理发送至 DeepSeek，图片和文件本体不会发送。模型只返回结构角色，不改写原文；服务失败时自动回退本地规则。
6. 点击“生成智能美化 PPT”，完成后检查：
   - **页面预览**：自动分页、真实模板槽位的近似展示与静态版式；
   - **内容对账**：每条原文、来源、数字及回读结果；
   - **耗时分析**：本次内容解析、可选 AI 分析、模板解析、规划、JSON 序列化、PPTX 写入、结构回读与审计耗时。
7. 下载 PPTX，在 WPS 中继续编辑，并用幻灯片播放模式检查转场。

生成在当前浏览器标签页中进行。复杂文件处理期间页面可能短暂无响应，请不要关闭或刷新；刷新会结束任务并清除未下载结果，请先下载再刷新。

## 输入、隐私与任务文件

- 支持 DOCX、Markdown、TXT、PPTX，单文件最大 25 MB，空文件与损坏的 Office 文件会被拒绝。
- 默认情况下，源文件、图片、页面计划、对账和 PPTX 结果只在当前浏览器内存中处理，不上传到静态服务器，也不写入云端任务数据库。
- 主动开启 AI 后，待分类的标题／正文文字块会经 Vercel `/api/analyze` 转发至 DeepSeek；发送内容包括文字块 ID、当前类型、层级和原文，不包括图片、整个 Office 文件或 PPTX 字节。DeepSeek 只承担结构分类，不用于改写内容。单次最多 400 块、60,000 字符和 100 KB，超出限制会回退本地规则。
- 结果区会明确显示 AI 已应用及调整块数，或显示未应用原因和本地回退。AI 未勾选时 `AI 结构分析` 耗时为“未测量”；勾选后记录真实请求耗时，并计入核心流程总耗时。
- 页面关闭或刷新后，未下载的生成结果不可恢复；浏览器下载目录中的 PPTX 不受影响。
- 开发者构建、Vercel Secret 和可选旧本地 API 的环境说明见 [部署说明](DEPLOYMENT.md)，这些都不是普通访问者的使用前提。

## 套用 PPT 模板

- 模板是独立于内容文件的第二份 PPTX，最大 25 MB。程序扫描全部模板页，识别真实标题、正文、图片和表格槽位，再按每页内容的数量、类型、容量与缩放程度选择合适版面；不再只参考第 1、2 页提取主题样式。
- 下载稿以原模板为包壳，克隆每个入选页面的 slide XML 与关系，保留对应的 slideLayout、slideMaster、theme、背景、装饰形状、Logo 和图片媒体，并保留模板原始页面尺寸。
- 标题与正文写回真实文字框并保留其段落和字符样式；图片使用原生图片关系，表格替换槽写为原生 `a:tbl`。未使用的模板示例文字与示例表格会清除，不把整页渲染成截图冒充可编辑内容。
- 网页预览只近似展示选中槽位、背景和文字排版，不能完整呈现模板全部装饰与真实渲染效果；最终版面以 WPS 打开的下载稿为准。
- 模板原始切换与对象动画会移除，替换为当前 Morph、非黑场 Fade 和错峰入场；不保留原动画，也不生成可复用母版。没有可用标题与内容槽位的模板会明确报错，不会静默退回自生成布局。
- 模板字体不嵌入或安装。目标电脑缺少字体时由 WPS 替换，可能改变换行，应重新检查排版。
- 内容 PPTX 自身的模板仍不保留。若既要重排初代 PPT 又要套版，请把初代 PPT 作为内容文件，把目标视觉模板放在第二个入口。
- 模板装饰与背景媒体不属于来源正文，不计入原文保真对账；所有来源内容文字、数字和图片仍按原规则检查。

## 识别规则与任务状态

- Markdown 支持 `#` 多级标题、Setext 标题、嵌套列表和连续换行段落；粗体、斜体、删除线、行内代码与链接只保留真实文字，独立的 `**` 等格式符号不会成为正文。TXT 会结合章节标记与编号间隔区分“章节标题”和“连续要点”，不再把所有 `1.` 都机械拆成章节。
- DOCX 读取 Title、Subtitle、Heading、大纲级别、嵌套编号与表格内文字；PPTX 按实际播放顺序读取，并支持组合坐标、默认字号、表格及 SmartArt 文本。未使用真实模板表格槽时，PPTX 表格按原行列用原生矩形和文本框重建，不是原生 table 对象；SmartArt 只提取文字后重排。
- PPTX 入口保留每张原始内容页的边界、完整小标题编号和文本框分组。只有原稿真实项目符号才显示为要点，普通多段正文继续按换行保留，不会因为文字较短、字号较大或文本规则、AI 返回异常而自动提升为小标题或拆成编号条目。
- 导入正文使用 1.3 倍行距，字号与文本框容量联动。短侧栏标签会尽量改为正文上方的小标题；密集栏按原顺序重排并收紧无效间隔，单栏双长文本框会利用左侧空白并按 WPS 字体行高预留余量。单块超过 12 个已有 `•` 段落的参考文献按原顺序排为双栏，不改写文献内容。
- 来源目录只有在全部有效条目都能对应后续章节时才与自动目录合并，避免同一目录重复成页；合并后保留原标题、原始条目和章节计数。无法匹配的自定义目录不会删除，仍作为正文保留。
- 跨页重复页眉页脚、同页多个零填充卡片序号及与带序号标题对应的独立序号会归入装饰；页眉页脚中的窄规则英文品牌／导航标签也可识别。英文来源、中文脚注和不能确认的小字不按该品牌规则删除。
- 在线生成不再连接本地任务 API，也没有服务重启造成的“任务一直未完成”。组件加载、Office 解压、XML 解析和原文回读失败会直接显示原因。
- 浏览器不支持 Office ZIP 解压时会明确提示升级浏览器；静态资源网络错误会显示中文提示，不再暴露 `Failed to fetch` 或要求检查本地启动窗口。
- 若 Office 文件内部结构无法读取，请在 WPS 中另存为新的 DOCX/PPTX 后重试；不要把刷新后消失的任务当作仍在后台生成。

## 可编辑对象、字体与素材

- 封面、正文、数字、卡片、圆环、章节游标和进度条均由原生文字与形状构成，不使用整页截图或视频。
- 不嵌入或安装额外字体。默认正文指定 `Microsoft YaHei`，使用模板时优先写入模板字体声明；网页使用系统字体回退，目标系统缺少字体时仍可能替换并改变换行。
- Markdown 可引用随附 PNG/JPEG，图片按原始宽高比嵌入为原生图片对象；外部 URL 不会自动下载。DOCX 内嵌原图尚未进入重建链路。
- PPTX 会保留原页 PNG/JPEG/EMF 图片及其相对位置，正文与表格自动避让内容图片，大幅背景图放在文字底层。EMF 在网页预览中只显示“原图已保留”提示，下载 PPTX 后可在 WPS 中查看真实图像。
- Markdown 的 `$...$`、`$$...$$` 和 DOCX 数学内容会以 Cambria Math 可编辑文本呈现；当前不排版 LaTeX，也不生成原生 Office 公式对象。
- PPTX 入口不保留原模板、母版、原始动画和对象身份。请保留原文件，把结果视为重排版样稿。
- 后续使用外部素材时，只应使用有权使用的 PNG/JPEG；生成图必须标为生成图或示意图，不能称为实拍。

## 动画与兼容性

- 章节游标与进度条通过同名对象参与 Morph by Object，用来表达章节进度。
- Morph 目标时长 650 ms；不支持时降级为非黑场 Fade，目标时长 450 ms。
- 正文采用错峰 Fade 入场，单条目标时长 320 ms。
- 网页预览只用于检查内容与静态结构，不代表 WPS 播放验收。
- 本轮浏览器生成的 5 个金标准文件已在本机 WPS 完成打开和逐页 PNG 导出，共 20 页；实看未发现文字裁切、错位或意外遮挡，测试图片与公式文本按原内容显示。
- 6 页示例已在真实放映窗口按第 2–6 页顺序导航并抓帧，可见章节游标连续移动和正文渐进入场；所检查帧未出现全黑转场。画面顶部黑边来自放映窗口的宽高比留边，不是整页黑场。关键时刻抓帧不等于连续逐帧验证，也不代表所有 WPS／PowerPoint 版本均已通过。
- 本轮另用一份 18 页复杂导入稿完成本地回归：最终文件 18 页均由 WPS 成功导出，实看第 7、8、9、11、12、13、14、15、16、17、18 页，检查长表格、1.3 倍行距正文、双栏文献、EMF、内容图片和背景图文字。第 16 页曾发现真实行间重叠，修复后重新导出确认完整，其他页面渲染哈希未变化；第 17 页文献完整，辅助拼图的裁切不代表 PPT 裁切。放映窗口已成功导航到第 9、16、18 页。静态导出与顺序导航不等于连续逐帧动画验证，该结果只代表本机当前 WPS 与这份回归稿。
- 真实模板功能使用非私密 6 页示例重新完成浏览器与 WPS 验证：纯文字稿选用模板第 1、3、3 页，共 3 页、5/5 条原文匹配、5 处错峰 Fade，保留 21 处模板装饰且未残留示例正文；媒体稿共 2 页、3/3 条原文匹配，包含 1 个原生表格和新增原生图片。两份下载稿均由 WPS 成功打开并逐页导出，已逐张实看全部 5 页：真实卡片与母版装饰保留，Markdown 格式符号未进入正文，普通正文保持正文层级，图片与表格位于真实内容区域，没有全页遮挡。媒体稿中的黑色矩形来自 1×1 黑色测试图片本身。这是当前文件的本机静态渲染检查，未进行连续逐帧动画验收，也不代表所有模板均已通过。

## 内容准确性与已知限制

- 自动分页不改写原文、数字和结论，不补写未提供的成绩、价格或承诺。
- 回读遗漏会阻止网页交付，但字符串匹配不能证明语义、阅读顺序或视觉层级完全正确。
- Markdown/TXT 可用 `备注：`、`> 备注：`、`<!-- 备注 -->` 或 `::: notes` 区块写入讲稿；这些内容只计入备注数量，不进入幻灯片。使用 Python CLI 时还会保存在 `content.json` 的 `notes` 中。PPT 演讲者备注也会单独读取。
- 无明确大纲 PPT 的跨页叙事、复杂主副标题和自由格式备注仍可能误判。
- 页眉、页脚、页码和卡片序号通过跨页位置、字号、重复情况及同页序号上下文识别；英文品牌／导航标签仅按窄规则处理。小号但有意义的内容仍可能误判为装饰，复杂 PPT 仍需结合内容对账人工复核。
- 三套主题与内容适配布局仍由规则选择，不能承诺所有行业与复杂文稿自动达到高级定制设计水平。
- 文本已加入中英文宽度估算和原生自动缩放，但真实文件仍必须结合 WPS 渲染检查换行、错位与遮挡。

## 耗时口径

“核心流程耗时”包括内容解析、可选 AI 结构分析、可选模板解析、页面规划、计划 JSON 序列化、PPTX 原生写入、结构回读和原文保真审计；不包含用户选择文件、浏览器读取、静态资源加载、下载、WPS 渲染和人工审阅。未选择模板或未启用 AI 时，对应耗时记录为 `null`；启用 AI 后即使失败回退，也记录本次真实请求耗时。在线版不再包含三次 Python 进程启动或状态轮询。未精确测量的项目应记录为 `null`，不能用估算值冒充实测。

本轮真实模板浏览器与 WPS 验证未单独记录可复核的分阶段耗时，因此不沿用旧主题提取路径的 90 ms 数据。网页结果区仍会显示每次实际生成测得的各阶段耗时。

本轮 18 页复杂 PPTX 的本地浏览器实测：97 条原文、100% 匹配，核心流程 729 ms，其中内容解析 460 ms、页面规划 13 ms、计划 JSON 写出 3 ms、PPTX 原生写入 60 ms、结构回读 117 ms、原文保真审计 77 ms。该数值是单次运行结果，不是稳定性能承诺。

GitHub Pages 公开地址实测：示例 Markdown 为 6 页、18/18 条匹配，核心流程 66 ms，下载产物通过独立 ZIP/XML 回读。此前在线浏览器引擎实测：TXT 为 3 页、6/6 条匹配，25 ms；DOCX 为 2 页、5/5 条匹配，7 ms；Markdown 加图片为 3 页、5/5 条匹配，8 ms；PPTX 回转为 6 页、24/24 条匹配，39 ms。它们只代表本机、当前样例和当次浏览器运行，不是大文件性能承诺。

旧本地原型实测样例：Markdown 为 6 页、18/18 条匹配，核心流程 86.706 ms、浏览器任务状态 607 ms；PPTX 回转为 6 页、24/24 条匹配，核心流程 46.564 ms、浏览器任务状态约 508 ms。这些历史数字不能冒充在线浏览器性能。
